## Context

### Objective

Ship three client-facing fixes, then set up `/save` and `/load` so a new session
can resume without re-reading the codebase.

### What changed

- **DEC-068** — inventory items can be renamed from the Edit stock dialog
  (migration `00021`; admin-only, and the name is global because `products.name`
  backs the inventory row, the sale catalog and reports). A third expense type,
  "Office Supplies / Others" (migration `00020`), with its own summary and Excel
  column. The four long-standing "pre-existing" test failures turned out to be an
  accessibility defect, not stale tests: `FormField`'s `<label htmlFor>`
  overrode the DatePicker trigger's accessible name, so the button announced only
  "Date". Fixed with `labelAsText` plus `aria-labelledby` (label + value).
- **DEC-069** — "Office" is a third *Assign to* target, so office-supplies spend
  is no longer forced onto an arbitrary rider or vehicle (migration `00022`).
  Fuel and repair still require a target. Also fixed the Expense Records sheet,
  which labelled every office-supplies row "Repair".
- **DEC-070** — every list feeding the report export now pages. The client's
  export started at Oct 11 instead of Sept 25 because PostgREST caps a response
  at 1,000 rows and `listSales` never requested page two; ordering newest-first
  silently discarded everything older.
- **`/save` and `/load`** — project commands registered in `opencode.json`,
  backed by `scripts/session/save.mjs` and `workflow/session.md`.
